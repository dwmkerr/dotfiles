# terminal

For terminal colours, I like [atom-one-dark-terminal](https://github.com/nathanbuchar/atom-one-dark-terminal).

The repo has been cloned here for quick access, but should be updated from time to time.

## iTerm2 profiles

Profiles in `iTerm2/` are managed as dynamic profiles. Each JSON file defines a single profile. See the main README for install instructions and `identities/README.md` for identity-specific profiles.

## kitty

`kitty/kitty.conf` mirrors the iTerm2 look (One Dark palette, Monaco 12,
opaque background, left option as Esc+). It is here for the Kitty graphics
protocol, which lets terminal programs such as whatsapp.nvim show pictures,
also over SSH. `make` links the files into `~/.config/kitty`.

kitty opens fullscreen in the current Space, with no slide animation.
`kitty.conf` cannot set the startup state, so `macos-launch-services-cmdline`
passes `--start-as=fullscreen` when kitty starts from the Dock or Spotlight.
`cmd+enter` toggles fullscreen, as in iTerm2.

kitty sets `TERM=xterm-kitty`, and SSH passes that to the remote machine. tmux
there refuses to start without the matching terminfo entry, so copy it across
once per remote host:

```bash
infocmp -x xterm-kitty | ssh -T -o RemoteCommand=none <host> tic -x -o '~/.terminfo' /dev/stdin
```

After that, `ssh <host>` from kitty works as from iTerm2, `Host air` from the
iTerm2 profiles section included.

## OBS Terminal Recording Setup

1. **OBS**: Create scene → Add "Window Capture" source → Select Terminal window
2. **Global Hotkeys**: OBS Preferences → Hotkeys → Enable "Global Hotkeys" (requires Accessibility permissions)
3. **iTerm**: Disable `Cmd+Shift+P` conflict: Preferences → Keys → Key Bindings → Add `Cmd+Shift+P` as "Ignore"
4. **Recording**: `Cmd+Shift+R` (start/stop), `Cmd+Shift+P` (pause) - works from any app
5. **Files**: Right-click OBS → "Show Recordings" to find .mp4 files for SharePoint upload

## Recording and Displaying Keystrokes

[KeyCastr](https://github.com/keycastr/keycastr) shows your keystrokes on screen during recordings.

1. **Install**: `brew install --cask keycastr`
2. **Toggle on/off**: ⇧⌃⌥K

## iTerm2 profiles

Profiles are generated by `make iterm-profiles` from `iTerm2/base.json` plus one
overlay per profile in `iTerm2/profiles/`. Shared keys such as the keyboard map,
colours and font live only in the base, so a change to them is made once.

| Profile | What it does |
|---------|--------------|
| `dwmkerr` | Loads the dwmkerr identity, attaches `tmux -L dwmkerr` |
| `gaspode` | Loads the gaspode identity, attaches `tmux -L gaspode` |
| `gaspodeair` | `ssh air`, landing in the same gaspode session on another machine |
| `dwmkerr-recording` | Clean shell for screen recordings, no tmux |

Private overlays in `~/.shell.private.d/iterm2/*.json` are merged in as well, so an identity whose name should stay out of this public repo can still have a profile. They are backed up and restored with the identity files by `make private-files-backup` and `make private-files-restore`.

`gaspodeair` needs a `Host air` stanza in `~/.ssh/config`, which is private and
deliberately not in this repo - the hostname is not published here:

```
Host air
  HostName <host>
  User <user>
  RequestTTY yes
  RemoteCommand tmux -L gaspode new-session -A -s gaspode
  ServerAliveInterval 30
```

Editing that private file repoints `gaspodeair` at a different network path
without a commit. Two machines attached to the shared session mirror each other,
and `window-size smallest` in `tmux.conf` holds the window steady for both.
